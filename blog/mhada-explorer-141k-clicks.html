1. Why I built it

On 24 August 2026, MHADA opened its Pune housing lottery: 4,462 homes across 168 scheme rows, split between PMC, PCMC and social housing, with 15 reservation categories. The official information was correct but hard to use: long PDFs, scheme tables and notices published at different times.

People applying had three simple questions:

  1. Which schemes can I actually apply for, given my income, category, area and budget?
  2. Is my name on the list?
  3. What will the EMI be, and am I eligible?

MHADA Pune Explorer answers those three questions, in English and Marathi. It is independent and not affiliated with MHADA; every application and payment still happens on the official portal.

2. A site with no server

The data changes on a fixed schedule (advertisement, deadline, draft list, final list, draw), not every second. So there's no reason to run a server. The whole site is static files on Cloudflare Workers static assets, served from Cloudflare's edge.

16

That's 207 HTML routes. Clean extensionless URLs and 301 redirects to one canonical address are handled with Cloudflare's _redirects and _headers files. In the last 30 days the site served 970K requests and 25 GB with a 0.00% server-error rate on Cloudflare's free plan.

3. Searching 2.68 lakh applications without a backend

The draft list has 2,68,670 accepted and 5,398 rejected applications. Shipping all of that to every visitor would be slow, and running a database for it would be overkill.

A Python script turns the official draft export into small JSON files, split by the first characters of the search key (prefix sharding). When someone types their name or application number, the browser fetches only the one small shard that can contain it. The shards are static files, so Cloudflare caches them like everything else.

The idea (simplified)
// build time (Python): data/draft/<prefix>.json for each key prefix
// run time (browser):
const key    = normalise(query);            // name or application number
const prefix = key.slice(0, PREFIX_LEN);
const shard  = await fetch(`/data/draft/${prefix}.json`).then(r => r.json());
const hits   = shard.filter(row => row.key.startsWith(key));

The same page shows competition per scheme: on average there were 60.2 applications for every home.

4. The scheme finder

The 7-step scheme finder asks for unit size (1 RK to 2.5 BHK), income group (EWS or LIG), planning authority, preferred areas, reservation category, possession year and budget. It scores every scheme from 0 to 100% for that person. Results can be shortlisted (saved in the browser) and exported as CSV.

Why "finder" and not "list": 168 rows is too many to read, and the rules are easy to get wrong. Income limits, for example, changed with a corrigendum on 5 September. The finder applies the current rules for you.

5. Built to be found

Nobody types a URL for a lottery guide. People search "MHADA Pune draft list", "MHADA Pune important dates" or a scheme name. So every common question got its own page, and each page says clearly what it is:

  • A page per search intent: one page per scheme, area, BHK size and budget band, so a specific search lands on a specific answer.
  • Structured data: FAQ, breadcrumb, site search and app markup (schema.org), so search engines understand what each page is.
  • A complete sitemap with 208 URLs, submitted to both Google and Bing.
  • Marathi as well as English, because many applicants search in Marathi.
  • llms.txt and llms-full.txt with the schedule, quotas and route map, so AI assistants can answer questions about the lottery correctly and cite the site.
  • Fast pages: static HTML, self-hosted fonts and icons, and a 79% cache-hit rate at the edge.

7. Traffic follows the government calendar

The traffic graph isn't a smooth line. It's a set of spikes, and every spike lines up with a date in the official schedule:

DateEventWhat happened to traffic
24 AugApplications openSearch traffic starts
Late Oct – 1 NovApplication deadline (extended to 1 Nov)Biggest peak of the quarter
Early – mid NovWaiting periodQuiet
23 – 24 NovDraft list published; objection cut-offSharp spike back up

That's why "important dates" is the second most visited page. The lesson for anyone building something similar: know the calendar your users live by, and have the right page ready before the date.

8. Staying honest

A site about a government lottery has to be careful. Every page carries a clear notice that it is independent and not affiliated with MHADA, and every action links to the official portal. A Python check runs over all deployable pages before each release. It verifies the disclaimer and consent banner, publisher details and ads.txt, and checks that no page uses gambling-style wording. The site helps people understand a public housing process; it doesn't sell them a "chance".

9. Lessons

  • Static is underrated. 970K requests a month, zero server errors, no server to look after.
  • One page per real question beats one big page that answers everything.
  • Build for AI answers too. Clean structure and llms.txt led to 34.8K Copilot citations.
  • Follow your users' calendar. The traffic spikes were predictable weeks ahead.
  • Shipping to real users teaches you things side projects don't: deadlines, corrections, and people who need the answer today.
